# Player considered reconnected before fully loading the game page

## Description
When a disconnected player starts navigating back to the game page, the system considers the player **reconnected before the page is actually loaded**.

This causes the opponent's client to believe the player has rejoined the game even though the player has not yet completed the navigation and cannot see the game board.

## Environment
- Local environment
- URL: `http://localhost:5173`
- Browsers: (e.g. Chrome)
- Test case: **Reconnection Timer Cancellation**

## Steps to Reproduce
1. Start a game between **Alice** and **Bob**.
2. Close **Alice's browser/tab**.
3. On **Bob's browser**, observe the **"Opponent Disconnected"** warning and the **30s countdown timer**.
4. On **Alice's browser**, type `/game/{gameId}` in the address bar but **do not press Enter yet**.
5. Observe the behavior on **Bob's side**.

## Expected Result
- Alice should only be considered **reconnected after the game page is actually loaded**.
- Bob should continue seeing:
  - the **disconnection warning**
  - the **countdown timer**
- The timer should stop **only after Alice successfully reconnects to the game room**.

## Actual Result
- As soon as Alice types the `/game/{gameId}` URL (before pressing Enter), she is **already considered reconnected**.
- On Bob's side:
  - the game considers Alice **present again**
  - the board becomes **unlocked**
- On Alice's side:
  - the **game board is not yet visible**
  - the page has not been loaded yet.

## Impact
The game state becomes inconsistent:
- The opponent believes the player has reconnected.
- The reconnecting player has not actually loaded the game yet.

This may lead to incorrect gameplay states or confusion.

==== Sub-issue #274: Joins room successfully ====
Labels: (none)
Assignees: (none)
## Bug: Player Cannot Reconnect to Game After It Has Completed

Test 8.

### Description
When a player disconnects during a game and the opponent finishes the game while they are offline, the disconnected player cannot reconnect to the game afterward.

The expected behavior is that the player should still be able to reconnect and receive the final game state, even if the game has already ended.

### Steps to Reproduce

1. Start a game between **Alice** and **Bob**
2. Alice disconnects (close tab / refresh / network drop)
3. Bob continues playing
4. Bob makes the winning move
5. The game ends and Bob sees the victory screen
6. Alice reconnects or refreshes the page

### Expected Behavior

When Alice reconnects:

- The client successfully rejoins the game room
- The server sends the final `game_state`
- The board shows the **final state**
- The **winning line is highlighted**
- A **Game Over modal** appears with the message **"You Lost"**
- Alice can see the result of the game even though she was disconnected
- The **"Back to Lobby"** button works normally

### Actual Behavior

- Alice cannot reconnect to the game
- The client fails to rejoin the game room
- No final `game_state` is received
- The game view does not load for Alice

Meanwhile, Bob's client still correctly displays the final game screen.

### Possible Cause

The backend likely prevents joining a game room when the game status is `"completed"`.  
Reconnection should still be allowed so the player can receive the final game state.

### Environment

- Browser: Any
- Transport: Socket.io
- Scenario: Reconnection after game completion

### Notes

Page refresh counts as a **disconnect + immediate reconnect**, so the server should allow the player to rejoin and retrieve the current game state regardless of whether the game is still in progress or already completed.
